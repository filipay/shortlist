# Quick Task 260929-i46: Extract the required years of experience

**A deterministic, description-derived years-of-experience floor now steers the existing `seniority` ranking factor as a quoted user-turn soft hint — never a hard filter, no new column, no migration, no extra LLM call.**

## Accomplishments

- `required_experience_years()` reads the leading number of a range (the floor) from a listing description; `required_experience_fragment()` returns the exact matched substring. Both derive from one private matcher, so they cannot drift.
- Clause-scoped qualifier exclusion skips preference language (preferred / ideally / desirable / nice to have / advantage / beneficial / an asset / bonus / a plus) while letting a clean clause win over a qualified one in the same sentence.
- `_required_experience_hint()` is wired into `build_ranking_parts()` beside the work-mode hint: the hint names the stated floor, quotes the matched fragment, tells the model to weigh evidenced experience against it, and states a shortfall may only lower the `seniority` sub-score and must be named in the rationale.
- The hint is a user-turn *addition only* — `RANK_SYSTEM_PROMPT` equality is asserted on a ranking call carrying a stated floor, and no listing is filtered, hidden or zeroed.

## Decisions Made

- Skip-and-continue on a non-positive floor: `"0-2 years"` alone yields `None`, but a later clean figure in the same description is still usable. This can never return a bad value and matches the stated behaviour.
- The hint uses the same `Any`-typed `getattr(listing, "description", None)` access pattern as the existing listing helpers, so it works against both ORM rows and the `SimpleNamespace` test shape.
