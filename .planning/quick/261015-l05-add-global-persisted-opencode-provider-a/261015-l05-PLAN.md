## Problem

All five completion callers currently pass settings.opencode_model. The adapter resolves this bare identifier by sorting matching providers, so duplicate model IDs cannot express an exact provider choice. Tailored artifacts separately stamp the current environment model, even when compilation happens after generation. The existing ProviderModel and wire builders already preserve separate provider/model identifiers.

## Goals / Success Metrics

Saving B/X must send B/X through session and completion builders even when A also advertises X. A fresh process must read B/X from SQLite. Removing B/X from discovery must fail before session creation, rather than use A/X or the environment. The normal settings page and unrelated settings saves must remain local-only. Only the existing explicit Test LLM backend POST spends a probe call.

## Options and Recommendation

Use two nullable identifier columns on the existing OperationsConfig singleton, a small dedicated repository, and an injected session factory on the real adapter. Resolve the global override once per completion and close that read session before discovery or token-spending I/O. This covers the extraction path without adding a database argument to every caller. The factory remains synchronous and health/discovery never load selection. Direct transport-test constructors can omit the injected factory and retain their existing isolated behavior.

Updating all five callers independently would distribute the same policy and add coupling to CV extraction. A second backend wrapper would duplicate the existing port for no extra user capability. Neither is needed.

The backend always supplies these template keys through _settings_context, including unrelated POST rerenders:

| Key | Exact value |
| --- | --- |
| llm_model_options | List of dictionaries with value, label, selected. value is compact json.dumps of the object {provider_id: string, model_id: string}, with that insertion order and separators (comma, colon) without spaces. label shows both identifiers. Sorted and deduplicated by the exact tuple. |
| llm_model_selection | Empty string for environment default, otherwise the same canonical JSON object string for the stored pair. |
| llm_model_current_label | Saved provider and model identifiers, or “Environment default: ” followed by settings.opencode_model. This is requested configuration, not confirmed served identity. |
| llm_model_discovery_status | One of not_loaded, ok, empty, unavailable, unauthenticated, models_warming. |
| llm_model_discovery_message | None or fixed, cause-appropriate safe copy. Never raw discovery.error, exception text, response payload or provider configuration. |

Options always include the environment-default empty value. The persisted pair is included and selected even without discovery, with its stored label; when discovery cannot confirm it, say so outside the option without rewriting the pair. On a successful refresh, merge the persisted pair with advertised safe ProviderModel pairs, not raw provider data. Escaping belongs to Jinja autoescape; never mark option labels/values safe. Treat JSON as an object, never split on slashes. Identifiers may themselves contain slashes, quotes or Unicode.

Routes/forms are fixed before writers start:

* GET /settings remains local-only and renders the saved pair plus the default option. GET /settings/llm-models explicitly refreshes safe discovery and returns the full settings page with populated options. Use a separate ordinary GET form/button; no JavaScript or automatic structured call.
* POST /settings/llm-model reads exactly model_selection from the existing read_form helper. Empty string clears both columns without discovery, restoring the environment default. A nonempty submission must decode to exactly two nonblank string fields provider_id and model_id, with bounded input length and no extra keys. Missing field or malformed value returns 422 without changing storage.
* For a new nonempty pair, discover and require exact tuple membership before storing; unknown returns 422, unavailable/auth/warming returns 503. Preserve the old pair on every refusal. An exact unchanged valid stored pair is an idempotent no-op and may succeed offline without discovery. Invalid existing storage is never silently treated as absence.
* All model save responses render the full settings page with the existing banner/error convention. Success is 200 after commit; errors preserve the saved selection and use safe fixed copy. No hidden “test” side effect, no token use, no LlmCall row for discovery/save. Existing same-origin middleware and current_user dependency apply to the new POST.
* The existing /settings/llm-test form, button ID, response sections, audit behavior and schema-constrained completion remain intact and separate. Copy must explain that it tests the SAVED choice, not unsaved dropdown changes.
