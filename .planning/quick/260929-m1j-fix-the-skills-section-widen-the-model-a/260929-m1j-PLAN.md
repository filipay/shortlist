<objective>
Fix the Skills section end to end: widen the model-assisted CV extraction schema so every
skill carries a group taken from the document's own grouping, and collapse the render so
each group is one labelled line instead of one row per skill.

Purpose: the fact store already models `Skill.group` as required and the template already
reads it, so every extracted skill currently shares a single fabricated group ("skills") and
renders as N near-identical rows. The real loss is upstream in the extractor, whose wire
schema (`_ExtractedSection.skills: list[str]`) carries bare labels only. This plan widens
that schema and groups the render — without inventing groups, without changing the fact-store
model, and without a migration or dependency.

Output: a wire schema that carries skill groups, prompt wording that asks the model to use the
document's own grouping, a grounded compile, and a template that emits one labelled line per
group.
</objective>
