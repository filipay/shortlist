## Reversibility

The weights editor is additive: deleting the `POST /settings/weights` route, its settings-page card and its CSS leaves the page as it was, and `ranking_config` simply retains whatever document was last written — `ranking_config_repo.read_weights` already falls back to `rubric.DEFAULT_WEIGHTS` when no row exists, so deleting the row restores uniform weights with no other change. The queue ordering change is the only behavioural edit: `QueueQuery.sort` defaults to `"score"`, so reverting means changing that default to the previous path or passing `?sort=recent`; the `"recent"` branch is today's code, kept verbatim, so the old behaviour is one default value away. The `min_score` predicate defaults to None, so it is inert when unset. The `SCORE_SORT_SCAN_LIMIT` bound, the ranking strip and the unranked badge are all deletable. No migration, no schema change, no data rewrite.
