<objective>
Make the first automatic LLM consumer in the pipeline safe to run unattended: two independent spend ceilings in `Settings`, reserve-then-call enforcement under an `asyncio.Lock` that refuses *before* the request, the rolling-24h aggregate over the `llm_calls` ledger, and the detached single-flight ranking lifecycle with the D-94 optional posture and D-95 per-listing isolation.

Purpose: RANK-08 and success criterion 5 are the cost-control spine of the phase. LLM calls are the dominant variable cost (PROJECT.md), and a cap that is checked after the call is not a cap. The detached shape is also what keeps the queue usable before ranking finishes (D-88).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings → cap decision | Operator-supplied ceilings gate every outbound model call |
| `llm_calls` ledger → cap decision | Persisted call counts gate the next call |
| listing content → call accounting | Untrusted listing text must not influence whether or how many calls are made |
| process lifetime → in-flight counter | A module-level counter is the only in-process spend state |

## Reversibility

The whole plan is a feature-flag-shaped change with no schema migration. Disabling ranking (the D-94 skip condition, which is already the default in the hermetic lane and whenever `cv.yaml` is absent) makes `run_pipeline` behave exactly as it does today: zero `llm_calls`, zero `scores` rows, `runs.ranked_count` NULL. The two `Settings` fields are additive with defaults, so removing them from `REQUIRED_SETTINGS_FIELDS` and `LIMIT_FIELDS` and deleting the Phase-5 block restores the previous config surface; the compose.yml and `.env.example` lines are inert if the fields are gone because pydantic-settings ignores unknown environment keys (`extra="ignore"`). `_reserve`, `_release`, `_in_flight`, `_RANKING_TASK`, `rank_calls_since` and `rank_cap_reason_for_run` are all deletable with no other importer. The D-102 guard rewrites are test-only and reversible by reverting the two test files.
