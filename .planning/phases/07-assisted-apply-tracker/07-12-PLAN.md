<objective>
Close G-07-7: the drafting call must return usable answers when the provider encodes a list-typed field as a single-key wrapper object `{"item": ...}`.

Purpose: the model's structured payload reaches the app with `ScreeningAnswer.evidence_ids` (a `list[str]`) wrapped as `{"item": <value>}`, and once as the empty string `""`. `_coerce_evidence_ids` (`app/domain/schemas/screening.py:37-53`) tolerates `None`/`str`/`list`/`tuple` but returns any `Mapping` untouched, so pydantic raises `list_type`; `_salvage` re-raises (correct — `list_type` is deliberately not tolerated), the stage returns `None`, and the route emits 502 `drafting_failed` with no rows written. The G-07-2 fix handled `evidence_ids=""` but not the `{"item": ...}` Mapping. The same class hit a tailoring call (`gaps[0].evidence_ids == ""`). The fix is a single shared unwrap helper applied to every list-typed field on the wire-adjacent schemas, converting invalid->valid only; every other shape keeps failing loudly (CONVENTIONS 1/2).

Output: `app/domain/schemas/_coerce.py`, the schema wiring across screening / cv / ranking, and the held-out fixture plus fail-loud and route/stage tests.
</objective>
