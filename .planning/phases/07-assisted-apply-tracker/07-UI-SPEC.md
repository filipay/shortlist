## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — no shadcn, no `components.json`. This is not a React/Next/Vite stack, so the shadcn init gate does not apply. The design system is a **bespoke Tailwind CSS 4.3.3 build, hand-extended and vendored** at `static/vendor/app.css` (mounted at `/static` in `app/main.py:57`, linked in `base.html:8`). |
| Preset | not applicable |
| Component library | none — server-rendered Jinja2 partials + HTMX 2 + Alpine 3. Reusable "components" are **CSS class tokens + HTML partials**, enumerated below. |
| Icon library | none — Unicode glyphs only. Existing precedent: `&#9733;` (`_listing_row.html:39`), the `—` em-dash placeholder (`app/web/filters.py:55`), `→` for transitions. Do not introduce an icon font or SVG sprite. |
| Font | `--font-sans` (system UI stack) for body; `--font-display` (ui-serif/Georgia) for headings; `--font-mono` for ids, codes, dates and machine tokens. All three are declared in `app.css` (theme block, line 2). |

**Rule for this phase:** extend the tokens and class vocabulary already in `static/vendor/app.css` and the markup already in `app/web/templates/html/`. **Do not introduce a second system.** New CSS is limited to (a) the `.badge-stage-*` variants mapped to existing semantic tokens in §Color, and (b) 1–2 phase-scoped wrapper classes named `apply-*` / `tracker-*` that copy an existing rule's declaration block verbatim (each such new class is called out below with the existing rule it mirrors).

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Existing anchor values (reuse, do not rewrite): `#content` padding `1.5rem 1rem 3rem` (24/16/48); `section` margin-bottom `2.5rem` (40); `.tailoring-review` padding `1rem` (16); table cell padding `.875rem 1rem` (14/16); `.settings-card` padding `1.25rem` (20).

**Exceptions:** the shipped sheet also uses Tailwind's default micro-steps *between* the 8-point values — 6px (`.375rem`), 10px (`.625rem`), 12px (`.75rem`), 20px (`1.25rem`) — throughout `app.css`. Phase 7 reuses those shipped rules unchanged rather than normalising them to 8-point (a rewrite would reflow every existing surface). **Touch targets:** every new icon-only or compact control (copy button, history toggle, stage filter chip) must clear **44×44px** (`min-height:2.75rem; min-width:2.75rem`) so the phone layout (UI-06 / Phase 8) is not hostile.

## Phase 7 Surface Contracts

Two surfaces. Both are **server-rendered, no-JS-degradable**: HTMX enhances, it never gates
reachability; Alpine enhances (copy, reveal), it never carries a state the server also owns.

### A. Apply package — `GET /listings/{id}/apply`

Routes mirror `app/api/tailoring.py` exactly: page shell + one action per behaviour, each
declaring `user: User = Depends(current_user)`. Template extends `base.html`, H2 `Apply package`,
back-link `Back to the listing` (mirrors `tailoring.html:15-18`).

The route computes **one** state string, `package_state`, and the template branches on that only
(mirrors `tailoring.py:130-146` — the template does no lookup, date arithmetic or settings read):

| `package_state` | When | Renders |
|-----------------|------|---------|
| `gated` | no `ok` cv_artifact exists for the listing (D-121) | `.tailoring-empty` panel, `data-state="no-ok-artifact"`, with the gated heading/body/CTA above. Nothing else on the page. |
| `disabled` | `Settings.tailoring_enabled` is false **and** no `ok` artefact (optional; only if the route adopts the kill switch) | `.tailoring-empty` with the existing skip label vocabulary |
| `ready` | an `ok` cv_artifact exists | The five blocks below, in order |

**Ready blocks, in order:**

1. **No-submit reassurance** — `<p class="apply-assurance">` with the reassurance copy, directly
   above the outbound link. This is the phase's product posture (APPLY-02): it must read as
   *designed*, not as a missing button.
2. **Outbound apply link** — `<a class="apply-link" href="{{ apply_url }}" target="_blank"
   rel="noopener noreferrer">Open the application form</a>`. `rel="noopener noreferrer"` is
   mandatory (the URL is untrusted listing data; the existing external-anchor rule,
   `listing_detail.html:37`). This is a real anchor, **never a form POST** — no submit path exists
   anywhere (APPLY-02).
3. **Verified PDF** — `<section><h3>Your verified CV</h3></section>` with:
   `<a href="/listings/{{ id }}/cv/pdf" target="_blank">Preview</a>` (inline PDF) and
   `<a class="cv-download" href="/listings/{{ id }}/cv/pdf?download=1">Download the exact PDF you'll send</a>`
   (mirrors `tailoring.html:72`). The route supplies this only when an `ok` artefact exists, so the
   block is unreachable when `gated`. Blocked/cancelled artefacts are never linked (D-118).
4. **Gap checklist** (D-123) — read-only `<ul class="requirement-list">` of the stored ranking gaps,
   each `<li class="req-gap">` (unmet) or `req-partial` (partial), reusing the exact markup at
   `listing_detail.html:94-99`. **No checkboxes, no tick state, nothing persisted.** Section hidden
   with the empty copy when no gaps are stored.
5. **Drafted answers** (D-124/D-127) — HTMX swap root
   `<section id="apply-answers" class="tailoring-review" aria-live="polite">`:
   - One block per question (settings-defined list ∪ ad-hoc). Each block: the question text, then
     either the stored answer (`<p class="answer-text">`) or `Not yet drafted.`
   - Under each answer: a **`Copy answer`** `type="button"` (class `button`; **not** accent) whose
     Alpine handler writes `navigator.clipboard.writeText(...)` from the adjacent `.answer-text`
     and flips its own label to `Copied` for ~2s. The answer text stays rendered text (never
     `|safe`, never an input's value) so with JS off it is still selectable and copyable by hand —
     the ResuMorph "preview, then insert, copy, or cancel" posture (FEATURES DF-12). The copy button
     must clear the 44px touch target (§Spacing).
   - **Evidence** per answer: `Evidence: ` + `<code>` chips for the fact/listing ids the draft used.
   - **Unsupported-claim warning** (D-125): when the answer carries an unsupported claim, an
     `.answer-warning` line (warning token, ⚠ glyph) renders **inside the same block** — a warning,
     never a block, mirroring the warn-not-block rule in `_cv_findings.html:6,27`.
   - **Add a question** — `<form hx-post="/listings/{{ id }}/apply/question"
     hx-target="#apply-answers" hx-swap="innerHTML">` with one `<input type="text" name="question">`
     in a `.field`, submit `Add question`. Re-renders the whole `#apply-answers` region.
   - **Draft action** — `<form hx-post="/listings/{{ id }}/apply/draft" hx-target="#apply-answers"
     hx-swap="innerHTML" hx-indicator="#draft-progress" hx-disabled-elt="find button">`, submit
     `Draft answers`, plus a progress line (mirrors `tailoring.html:36-41` /
     `_tailoring_review.html:66-84`):
     `<p id="draft-progress" class="htmx-indicator" role="status" aria-live="polite">Drafting answers — this calls the model, so it can take a minute.</p>`
   - Per-answer removal is the phase's **only destructive affordance**: a plain form (not HTMX)
     with `x-data="{}"` and `@submit="if (!confirm('…')) $event.preventDefault()"`, button class
     `cv-delete` — the exact pattern at `tailoring.html:55-62`.

Opening the page makes **no LLM call** (D-122): the route assembles from stored data only; the
drafting call is the explicit `Draft answers` action.

  | Stage | `<span class="badge badge-stage-{{ row.status }}">{{ row.status \| human_label }}</span>` |
  | Applied | `format_datetime(row.applied_at)` (em-dash when absent — never a fake date) |
  | Next action | `format_datetime(row.next_action_at)`, `.next-overdue` when `next_action_at < now` and the stage is non-terminal |
  | Latest note | one-line `.truncate` with the full text duplicated into `title=""`; the inline history carries the complete notes |
  | Actions | `History (n)` toggle + the `Move to` transition control |

- **Primary visual anchor:** the **Stage badge** column. It is the only colour-coded element in an
  otherwise neutral table, so the eye lands on the current stage first and scans the column top-to-
  bottom. The row's primary *action* is the `Update status` accent submit. In the needs-action view
  the **overdue** next-action cell (`.next-overdue`) becomes the second focal point. Don't add a
  competing accent to the table chrome (headers, filters, pager): accent stays with the badges'
  semantic colours and the one submit (see §Color). The queue table's identity anchor is the
  Listing/Company cell; the tracker keeps that cell first so the two tables read the same.
- **Needs-action view** (D-133): overdue rows first (ascending `next_action_at`), then upcoming
  (ascending); terminal stages (offer/rejected/withdrawn) excluded. Overdue rows keep the warning
  emphasis on the next-action cell.
- **Pagination** — reuse the two-way pager markup (`queue_list.html:84-104`) **keeping its existing
  `id="queue-pager"`** (there is no `.queue-pager` class — the rule is `#queue-pager`), with the two
  `hx-get` URLs pointed at `/applications/list`; `Settings`-fixed page size, server-side. The
  position span keeps `#queue-page-position`. No new id or rule is introduced.
- **Empty / filtered-empty** — mirror `queue_list.html:44-54` (`#application-empty` /
  `#application-empty-filtered` with a `Clear filters` link).
- **Unknown listing on the package page** → the 404 HTML fragment convention
  (`data-error="unknown-listing"`, `tailoring.py:122-127`).

### C. Inline history timeline (D-134)

- Per row: `<details class="stage-log" id="application-history-{{ row.id }}">` with
  `<summary class="…">History ({{ n }})</summary>` — the **existing** expandable-log markup
  (`runs.html:139-146`).
- Body: an HTMX partial `_application_history.html`, fetched on first expand
  (`hx-get="/applications/{{ id }}/history" hx-trigger="toggle once" hx-swap="innerHTML"` on the
  `<details>`), or server-rendered inline — either is acceptable; the partial is the requirement
  (D-134).
- Each entry: `<div class="stage-entry">` containing
  `<span class="stage-name">{{ from_status | human_label }} → {{ to_status | human_label }}</span>`,
  a `.reason-value` timestamp, and the note text. `from_status` NULL renders `created`.
- Empty: `No history recorded.` Nothing is editable here — the event table is append-only
  (D-131); "view and manage" manages the *current* stage, never the log.

### D. Status-transition control (D-128 … D-131)

- Form: `hx-post="/applications/{{ id }}/status" hx-target="#application-row-{{ id }}"
  hx-swap="outerHTML"` — the route re-renders **the whole row**, the `_action_forms.html` /
  `_detail_actions.html` inline-swap pattern (no manual reload).
- `Move to` `<select name="status">` limited to the guided set; an `Update status` submit (verb +
  noun — the shipped app never ships a bare `Save`: `Save weights`, `Save layout`, `Save search`). A refused
  transition returns the app's refused-action convention: a 4xx HTML fragment carrying
  `data-error` (`routes.py:198-213`).
- **Applied gate (D-129):** selecting `applied` reveals — and the server **requires** — an
  `ok`-only artefact picker (`<select name="cv_artifact_id">`, options from
  `cv_artifact_repo`'s ok-only selection, **latest preselected**). Alpine (`x-data` / `x-show`)
  reveals the picker on select change; with JS off the picker renders always and the server simply
  ignores it unless `status=applied`. A POST to `applied` with no, or a non-ok, artefact is a refusal
  fragment (`Record a verified CV first — …`) and writes nothing.
- **Notes + next-action inline edit:** a plain form, `hx-post="/applications/{{ id }}"`, returning
  the row; `Notes` field + `Next action` `<input type="date">` + `Save notes`. These are ordinary
  mutable columns (D-135); only status changes are append-only events.
- **Applied date** is stamped by the transition (D-130) and displayed read-only — never an input.

### E. Detail-page entry point

`listing_detail.html` gains one link beside the tailoring link (`:43`):
`<a class="listing-detail-link" href="/listings/{{ row.id }}/apply">Apply package</a>` — no new
stylesheet rule (the class already exists).
