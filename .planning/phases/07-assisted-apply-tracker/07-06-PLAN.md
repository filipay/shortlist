<objective>
Close G-07-2: the drafting call must survive the common recorded non-list payload shape and must not report a schema mismatch as "returned no answers".

Purpose: the UAT recorded two live calls that answered in ~46-52s with `status=invalid` and `error="validation failed: Input should be a valid list"`. The model produced a list-typed field (`ScreeningDraftResponse.answers`, or a nested `ScreeningAnswer.evidence_ids`) as something other than a JSON array. `TOLERATED_SCHEMA_ERRORS` deliberately does not cover list-type errors, so `_salvage` re-raises and the route collapses the failure into the same 502 copy it uses for a genuinely empty response. Each retry burns a real model call.
Output: schema-local coercion for the recorded shapes, a golden-payload fixture proving it, a hardened prompt, and a two-way refusal copy.
</objective>

  <name>Task 1: Coerce the recorded non-list screening shapes at the schema boundary, with a golden-payload fixture</name>
  <files>app/domain/schemas/screening.py, tests/domain/test_screening_schema.py, tests/llm/test_salvage.py</files>
  <action>
Add schema-local before-validation to `app/domain/schemas/screening.py` so the recorded list-type shapes are coerced rather than fatal, WITHOUT weakening the wire contract.

`ScreeningDraftResponse.answers`: add a `field_validator("answers", mode="before")` that returns `[]` for `None`; wraps a single answer-shaped mapping (a `dict`) in a one-element list; passes a `list`/`tuple` through as a list; and leaves every other shape untouched so pydantic still fails loudly. Do NOT switch `extra` away from `"forbid"` and do NOT add `extra="ignore"`.

`ScreeningAnswer.evidence_ids`: add a `field_validator("evidence_ids", mode="before")` that returns `[]` for `None`; turns a `str` into a list of its comma-separated non-empty stripped parts (a single id string therefore becomes a one-element list); passes a `list`/`tuple` through as a list; and leaves every other shape untouched. The comma-split is deliberately the only string interpretation; an unparseable string still ends up as an evidence id that fails the byte-exact grounding check and is surfaced as a warning, never silently dropped.

Why not widen `TOLERATED_SCHEMA_ERRORS`: dropping the top-level `answers` field to its default would silently erase every drafted answer. Keep that frozenset exactly as it is (`tests/llm/test_salvage.py::test_the_tolerated_error_allow_list_is_exact` pins it).

`tests/domain/test_screening_schema.py` (new): pin both directions. A recorded golden payload in which `answers` is a single object and `evidence_ids` is a bare string validates to exactly one answer with the evidence preserved. A valid array payload validates unchanged. An unknown extra key still raises `ValidationError` (the `extra="forbid"` contract survives the coercion). A scalar `answers` value that is neither mapping nor list still raises.

`tests/llm/test_salvage.py`: add a golden-payload test that routes the same recorded malformed shape through the production `_salvage(ScreeningDraftResponse, payload)` and asserts the answer survives — this is the hermetic stand-in for the live-model leg the gap asks for (the default suite stubs the backend and cannot otherwise catch this).
