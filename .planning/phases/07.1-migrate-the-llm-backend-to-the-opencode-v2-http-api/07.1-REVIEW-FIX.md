## Fixed Issues

### CR-01: V2 completion path has no transport-retry loop — `OPENCODE_MAX_RETRIES` is inert and `attempts` is misreported

**Files modified:** `app/llm/opencode_server.py`, `tests/llm/test_v2_generate.py`
**Commit:** `62511b5`
**Status:** fixed: requires human verification (behavioural/logic change)
**Applied fix:** Added the module-level `_post_with_transport_retries` helper (the
V2 twin of the V1 transport loop) and routed both the V2 session POST and each
`generate` POST through it, bounded by the same `budget` (`retries` argument, else
`settings.opencode_max_retries`) the V1 arm consumes. `ConnectTimeout` classifies
as `unreachable`; other timeouts as `timeout`. `attempts` now reports the issued
count (total `generate` POSTs, transport retries included; the session POST count
when session creation itself never completes) instead of `0`. The three prose sites
the review flagged as false statements (`opencode_server.py` retry-layers
docstring, `base.py` `retries` docstring, `config.py` `opencode_max_retries`
comment) are now accurate by construction — no doc rewrite was needed once the loop
exists. Added a parametrized transport-budget test (`budget` ∈ {1,2,3}), an
omitted-`retries`-honours-Settings test, and a generate-only transport-retry test.

### WR-01: `_extract_json` returns a balanced prose brace block instead of the JSON object

**Files modified:** `app/llm/opencode_server.py`, `tests/llm/test_json_extraction.py`
**Commit:** `f043c38`
**Status:** fixed: requires human verification (algorithmic change)
**Applied fix:** Replaced the commit-to-first-`{` scan with a parse-first search:
each balanced `{…}` block (via the new quote/escape-aware `_balanced_brace_span`) is
tried in order and the first that `from_json(..., allow_partial=True)` accepts is
returned. When no block parses the first balanced block is returned unchanged, and
with no balanced block at all (including an unterminated `{`) the input is returned
UNCHANGED — preserving D-141's fail-loud behaviour. Added a parametrized test with
the finding's two literal repro strings (`'use {x} then {"a":1}'` and
`'The set {a, b} is not JSON. Here: {"a": 1}'`).

### WR-02: V2 discovery hard-fails on `/api/provider` even though that payload is never read

**Files modified:** `app/llm/opencode_server.py`, `tests/llm/test_discovery_redaction.py`
**Commit:** `a58b44e`
**Status:** fixed: requires human verification (control-flow change)
**Applied fix:** A failed `/api/provider` GET (non-200, unreadable body, or transport
error) now degrades to the empty payload instead of returning `reachable=False`;
only the authoritative `/api/model` status is checked (D-146). `parse_v2_models`
already ignores the provider payload, so resolution is unaffected. Added a
parametrized test over provider statuses {404, 500, 503} asserting discovery stays
`reachable=True` with providers resolved.

### IN-03: A non-JSON 200 from V2 `generate` loses attribution (`attempts=0`)

**File:** `app/llm/opencode_server.py` (`_dig(response.json(), …)`)
**Reason:** Out of scope (Info). The fix mirrors `_classify_message_response` by
wrapping the V2 `.json()` calls in a `_failure(status="error",

improvement but overlaps CR-01's `attempts` semantics and deserves a dedicated change
with its own test rather than riding along with a Critical fix.
**Original issue:** `response.json()` on a 200 with a non-JSON body raises, escaping
to the outer generic handler → `attempts = 0`, discarding the issued count.
