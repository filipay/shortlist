<objective>
Surface the auth state the operator needs to act on (D-137/D-138): a `unauthenticated` cause on
failed calls (shipped by plan 07.1-01) is useless if the UI only ever says "LLM backend
unreachable". This plan puts `auth_configured` on the `/health` opencode report and renders an
auth-missing hint in the queue's LLM status line, computed from ONE helper so the report and the
strip cannot disagree.

Purpose: after the V2 migration an empty or rejected password is the single most likely reason a
call fails; the operator must be told "auth missing" rather than guessing.
Output: `auth_configured` on `/health`, an auth-missing strip line, and the tests pinning both.
</objective>
