# Phase 07.1 Plan 04: V2 model discovery (retargeted `/api/model` + `/api/provider`) Summary

**`discover_models` now speaks the V2 surface — `GET /api/model` + `GET /api/provider` — returning `(provider_id, model_id)` identifiers only, with the V1 `/config/providers` path retained and a one-shot cold-start re-probe**

## Accomplishments

- Added `parse_v2_models(model_payload, provider_payload)`: tolerant of the same malformed shapes `parse_providers` tolerates, and it copies ONLY the `(providerID, modelID)` pair — provider-level values (`key`, `name`, `options`) are structurally never read into a result (D-09/D-11).
- Retargeted `discover_models` to dispatch on the same `detect_surface` verdict as completion: V2 reads `/api/model` then `/api/provider`; V1 (and any `unknown` surface) keeps the original `/config/providers` + `parse_providers` path verbatim (D-148). The `llm.discovery` log keeps its `provider_count`/`model_count` totals and adds `retried`.
- Added the Pitfall P3 cold-start tolerance: an empty V2 model list triggers exactly ONE bounded re-probe (never a loop); an honestly-empty registry still fails loud `model_not_found` downstream (D-145, via the retained `_resolve_model`).
- Rebuilt `tests/fixtures/opencode_providers.json` as a V2 `model`/`provider` payload with the credential sentinel retained, and retargeted the four-way redaction suite (identifiers only, endpoint contract, log/stdout/DB sentinel absence, failure-is-a-value) to the V2 paths. `_resolve_model`'s docstring now states the V2 `Model.Ref` requires the derived `providerID`.

## Decisions Made

- **D-146 honoured:** `discover_models` is retained (not deleted) and retargeted; `_resolve_model` is untouched in behaviour and still derives the provider from the server's own discovery (A1), failing loud on a miss.

- No provider-list filtering: the model payload is authoritative for the pair (a cold server can legitimately return an empty `/api/provider`, and filtering would drop real models).
