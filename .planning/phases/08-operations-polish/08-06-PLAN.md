# Plan 08-06 — The prune preview measures regular files, and says so

**As a** job-seeker reading the prune preview before I destroy anything, **I want to** be told a freed-size figure that was actually measured, and to be told plainly when part of it could not be measured, **so that** the preview never presents an impossible number as a fact.

<objective>
Close gap **G-08-1**: the operator's live walk of the prune surface read `This will delete 4 artifacts · 117043.0 GB.` — an impossible figure for four CVs, and a lie about the deletion's own impact. The formatter (`_human_size`) is provably correct, so the fault is upstream: `retention_repo._size_inside` returns `resolved.stat().st_size` for any path that resolves inside the artifacts root, with no `stat.S_ISREG` gate, so a directory, a device node, a FIFO, a socket, or a bind mount that reports a bogus `st_size` is summed and presented as a fact.

Purpose: the whole retention surface exists so that nothing is destroyed silently and no number on it is a guess (D-166, and this project's conventions on fail-closed honesty). A preview that overstates the freed space is exactly the failure mode CONVENTIONS rule 2 exists to prevent: a measurement that cannot see what it needs must say so, never produce a confident total.

Output: a regular-file gate in the one measurement site, a diagnostic trail for the next live walk, the unmeasurable count surfaced in the preview summary, the amended UI-SPEC row, and the tests that pin the failure class.

This is a surgical correction to a shipped surface (08-05). It adds no category, no route, no migration, no dependency, and no configuration knob.
</objective>

### One correction to the gap register (read this before you trust the register)

The register says `settings.html:338` "never surfaces `missing_files`". That is **stale**. `settings.html:339-341` (added in `9d4b74b`, the 08-05 Task 1 commit) already renders a separate line:

> `{{ prune_preview.missing_files }} stored path(s) were missing or outside the artifacts directory and were not measured.`

So the honest statement of the defect is narrower than the register: the counter exists and one line shows it, but (a) the counter only ever counts *missing* and *outside-root* paths — a non-regular entry is measured and summed, not counted; (b) the count is not in the summary sentence, so the size still reads as complete; (c) the copy does not name the non-regular class; (d) the UI-SPEC declared row does not mention the unmeasurable count at all. This plan fixes all four. Do not "fix" the register text; fix the code and the copy.

### The gate this plan ships, and the gate it deliberately does not

Ship: `stat` once, return the size only when `stat.S_ISREG(st.st_mode)` is true; everything else (directory, device, FIFO, socket, a `st_size` we cannot trust) counts as not-measurable and returns `None`, feeding the existing `missing_files`.

Do **not** ship a plausibility bound against the filesystem's total or any other cap. A cap is a second guess layered on a guess, and it would silently rewrite a genuinely large regular file's size. The todo's candidate direction 2 is explicitly rejected; the todo's candidate direction 1 plus visibility is the whole fix. The gate is correct because a regular file's `st_size` is the size the unlink will free; a directory's is not.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the database rows → the filesystem | A stored artifact path is `stat`ed to compute a size; a hand-edited or legacy row, or a bind mount, can make that number meaningless |
| the measurement → the preview sentence | Whatever the measurement returns is presented to the operator as a fact about the deletion's impact |
| the measurement gate → the unlink gate | The size gate and the unlink gate must agree about what "inside the artifacts directory" means, or one can measure what the other will not free |
| the new diagnostic events → the log | A logged path could disclose file existence if a `stat` were performed before containment |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-32 | Repudiation (a confident total that silently omits what it could not measure) | `retention_repo.preview` → the preview sentence | high | mitigate | The unmeasurable count rides in the summary sentence itself (`· N path(s) not measured`) whenever it is non-zero, and the reason line names the class.
