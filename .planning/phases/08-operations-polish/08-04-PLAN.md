# Plan 08-04 — The tool tells the truth about itself

**As a** job-seeker who wants to trust the queue before I trust it with my morning, **I want to** open one page and see whether the database, the model backend, the LaTeX engine and my CV are all in order, when the next run is, what the last one did, and what the recorded evidence says about the sources — **so that** an empty queue reads as a named reason rather than mystery.

> **MVP framing note.** The ROADMAP `**Goal:**` line for Phase 8 is an outcome, not a user-story sentence; the story above is derived from it plus PROJECT.md's Core Value and recorded rather than invented, matching the Phase 4 precedent.

<objective>
Ship the health surface: one shared dependency-report builder consumed by both the JSON endpoint and a new human page, a run-derived per-source status read that never touches a job board, the next-run and last-run lines, the durable skipped-run notice, and the read-only Adzuna promotion verdict as evidence.

Purpose: RUN-07 asks that system and source health be checkable from a health endpoint surfaced in the UI. The phase's honesty contract depends on it: D-156 forbids a page view from being a scrape (a view must never put a request on a board that bans automation), D-157 forbids new measurement (the section is *assembly* of data that already exists), and D-158 keeps the promotion decision human by showing the computed verdict as evidence with its number rather than as a control.

Output: `dependency_report()` in `app/api/health.py` (key names unchanged), `app/api/health_page.py` with `GET /status`, the run-derived read and board-evidence builder in `source_repo.py`, `health.html`, the `Health` nav entry, and the page's test lane.

**D-155** governs the shape of that surface: health lives on a dedicated page carrying a system section plus the full per-source table, **and** the existing compact queue-page strip stays exactly where it is. The strip is not replaced, duplicated or re-specified — the page includes the same partial, which is what makes the two incapable of drifting apart.
</objective>

### Decisions this plan implements

- **D-155** — health lives on a dedicated page (a system section plus the full per-source table), **and** the existing compact queue-page strip stays. The strip is not duplicated or re-specified: the page includes the same partial.
- **D-156** — the source badge is computed from **recorded run outcomes** and recorded stop signals over the last N runs, not from the live probe stamp. The page reads the database only and never puts a request on a job board; the live probe survives as an explicit, separate operator action.
- **D-157** — the system section is assembly of data that already exists: the four dependency probes plus the next scheduled run plus the last run's status and one-line reason. It is not new measurement.
- **D-158** — the computed Adzuna promotion verdict is shown **read-only on the page as evidence**, with a link to the probe document. Nothing escalates or switches adapters automatically, and a manual enable-Adzuna control is out of scope.
- **D-08** — every dependency is *reported*, never raised, and a degraded dependency never changes the app's own status. The page inherits the `_health_strip` totality convention.
- **D-138** — the page and the JSON endpoint must not be able to disagree about opencode reachability or `auth_configured`.
- **Orchestrator decision C1** — the JSON `GET /health` keeps `/health` (it is pinned by 25 `.json()` assertions, the auth-seam route inventory, and `scripts/compose-smoke.sh`); the new HTML page gets its own path **`/status`**, and the nav entry keeps the label `Health`. The page route must not also declare `/health`.

### Known constraints

- The page must **not** call `probe_all`. That is the live board probe; putting it on a page view is the T-01-31 failure the phase exists to avoid.
- The badge vocabulary must reuse the existing `VALID_HEALTH` values (`ok`, `degraded`, `unreachable`) so the page's badges use the shipped `.health-ok` / `.health-degraded` / `.health-unreachable` / `.health-unknown` classes and the stylesheet-coverage guard needs no new tokens. An unknown value renders as `unknown`.
- The `.health-system` class the system grid uses was defined by plan 08-02 in `assets/tailwind/input.css`; do not author CSS here.
- `.planning/config.json` sets `workflow.human_verify_mode = "end-of-phase"`, so no mid-flight checkpoint is emitted; operator-run checks are harvested at end of phase.

### Not in this plan

No scheduling code (plan 08-03), no pruning (plan 08-05), no CSS (plan 08-02). Where the strip is a journey table, plan 08-02 already added its `data-label` attributes.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a page view → a job board | The page must never become a scrape; a view that contacts a board is a ban-risk regression (T-01-31) |
| the database → the rendered page | Rows carry upstream-derived text and recorded diagnostics; raw content must not reach the page |
| the scheduler object → the page | The scheduler may be absent, unstarted or paused; the accessor must be total |
| the recorded verdict → the operator's decision | Evidence must not become an action: no control may change which adapters run |
| an operator link → an external document | The probe-document link must resolve to a committed path, not a network asset |
