<design_decision>
## Locked choices this plan implements

These are decided; do not re-open them.

**O1 / A6 (user-pinned) — tailoring shares the rolling-24h ceiling and drops the per-run ceiling.** The tailor call records `run_id=None` (an interactive tailor has no run), so the per-run ceiling has no meaning. `llm_call_repo.rank_calls_since` filters `purpose == "rank"` and would let tailoring escape the cap, so this plan adds a purpose-aware `calls_since(session, *, purpose, now)` and has the tailoring call read it with `purpose="tailor"`, reusing the existing `ranking_max_calls_per_day` value. **No new Settings ceiling is added.** `rank_calls_since` stays as a thin delegating wrapper so the Phase-5 tests are untouched.

**The reserve-then-call lock is shared, not duplicated.** `app/pipeline/tailor.py` imports `_reserve`/`_release` from `app.pipeline.rank` rather than minting a second counter — one process, one in-flight budget, matching the shared 24h ceiling. Cross-module private import is deliberate and documented with a `ponytail:`-style note naming the upgrade path (hoist both to `app/pipeline/spend.py` if either module forks).

**A1 — similarity banding is advisory.** The `_GROUNDING_REVIEW_THRESHOLD`-style banding (80/55) informs confidence labels only and NEVER gates. The hard fail for `requirement_evidence` is structural: a non-`gap` `GapFinding` with no resolvable evidence id fails. The band lands in 06-02; this plan's Layer 1 check 6 is the structural half only.

**A2/A3 — the metric tokeniser.** Digit-core tokenisation with the decimal separator normalised to `.` and thousands separators removed; date-like numbers (each entry's `start`/`end` year+month cores) and layout artefacts excluded; a page number is excluded when it is a lone integer line whose value is ≤ `page_count`. Designed in 06-02.

**A7 — `app/verify` joins `SCANNED_DIRS`.** The verifier may import `rapidfuzz` (so it cannot live under `app/domain`, whose purity test forbids it) and must not hard-code a threshold literal. The `SCANNED_DIRS` addition lands in 06-02 with the thresholds.

**No migration.** `cv_artifacts.tex_path`/`pdf_path` are already nullable; the Alembic head stays `0004`.
</design_decision>

<objective>
**As a** job seeker working a ranked queue, **I want to** turn one listing into a CV tailored to it — expressed as a typed patch over my real CV facts, verified, compiled and downloadable — **so that** I can apply with a CV shaped to that job without ever risking a claim I cannot stand behind.

Prove the tailoring architecture end-to-end on one path, for keeps: replace the `apply_patch` stub with the real five-operation engine over the enumerated IDs, stand up the `app/verify` package with its Layer-1 pre-check, make the single `TailoringPatch` structured call with its own spend accounting, persist a `cv_artifacts` row, and expose the dedicated tailoring page that generates, compiles and serves the PDF.

Purpose: this is the phase where the ethical hard line becomes load-bearing code. Almost all of the dangerous machinery already ships (`apply_patch`'s id-grounding loop, `iter_fact_ids`, `RenderPlan.changes`, `render_plan_to_tex` with its escape choke point, `TectonicEngine.compile`, `extract_pdf_text`, `complete_structured`, the reserve-then-call lock, `cv_repo.current_version`). Proving the slice now — schema, pure domain, LLM call, verify hook, repository, route — catches an architectural dead end after one commit instead of after four committed layers. The two load-bearing shape decisions (the patch has no field that becomes PDF text; the call is one listing, ids only) are settled here because everything downstream derives from them.

Output: `app/domain/cv.py`'s real patch engine, the `app/verify` Layer-1 package, `app/pipeline/tailor.py`, `app/db/repositories/cv_artifact_repo.py`, the purpose-aware `llm_call_repo.calls_since`, the `app/api/tailoring.py` router, the tailoring page shell, and the `tailoring_enabled` switch.

**Scope fence for this plan:** Layer 2 (PDF-text post-checks, metric containment, the similarity band), the review fragment's full change log, the stale-patch guard's form round-trip, and the `ok`-only blocked-artifact failure-path suite are 06-02/06-03/06-04.
