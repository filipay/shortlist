<objective>
Close GAP 1 (CR-01, BLOCKER) and WR-03: make the Layer-2 check-4 region and allow-set construction correct so a valid tailored CV whose trailing structured content carries a digit is verifiable and downloadable again, and so one entry's dates can no longer silently excuse a token in another entry's region.

Purpose: `metric_containment` is the check the roadmap names for success criterion 3, and today it false-fails ordinary CV content (`AWS S3`, `Python 3`, `C++17`, `ISO 27001`, `EC2`) because the last entry's region runs to end-of-text and the Skills block is attributed to it while `_allowed_for_entry` enumerates only that entry's own fields. Because the only recovery is a fresh tailor (D-118), which re-runs the same check, preview and download are dead for such a CV. The same file also unions every entry's date cores into one global exclusion (WR-03), silently excusing a token in a region that does not contain it. Both are in `app/verify/numbers.py`, so they are fixed together in one plan (the file-overlap rule).

Output: a corrected `region_token_report` with region-local date, page-number and non-entry-structured exclusion; a bumped `VERIFIER_VERSION`; the committed `digit_skill_extract.txt` fixture and its `with_digit_skill` builder; and the passing/regression tests that pin both the fix and the negative control.
</objective>
