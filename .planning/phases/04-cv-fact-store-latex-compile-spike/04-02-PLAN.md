### Decisions this plan implements

- **D-73** — Tectonic arrives as a pinned tarball plus checksum: `ARG TECTONIC_VERSION` + `ARG TECTONIC_SHA256`, verified in the same `RUN` that downloads it, unpacked to `/usr/local/bin`. Single-line shell only, no heredocs (P10), mirroring the JobSpy SHA assertion.
- **D-74** — the package cache is primed by **compiling the fixture at image build**, which doubles as the build-time proof that the engine actually runs (the same shape as the existing migration smoke).
- **D-75** — a missing package fails **loudly with a documented rebuild**; compilation runs in Tectonic's cached-only mode so "offline" is literally true. Automatic fallback to the TeX Live image was rejected: the setting would silently override itself.
- **D-76** — the engine seam is real: a `LatexEngine` Protocol (`compile(*, tex, workdir) -> CompileResult`, failure-as-value) with `TectonicEngine` implemented and tested, selected through a DI factory next to `get_llm_backend` so tests can override it via `app.dependency_overrides`. `Dockerfile.texlive` is committed and the switch documented.
- **D-58** — `cv/` and `artifacts/` are gitignored volumes in the same class as `.env`; `compose.yml` mounts only `./data` today and `app/config.py` encodes the paths.

- **PLAT-04 / D-17** — the engine, its binary path, its cache path, its timeout and its offline mode are all `Settings` fields.

### Resolved-at-research details this plan must not re-derive

- The offline flag is **`-C` / `--only-cached`** — verified against Tectonic's own CLI reference.
- The **V1 CLI is the default in 0.17.0** (`-X` selects V2, `-Y` selects V1). Use the plain V1 form: `tectonic --only-cached --untrusted --keep-logs --outdir <dir> <file>.tex`.
- The untrusted control is **`--untrusted`**, equivalent to a non-empty `TECTONIC_UNTRUSTED_MODE`; it disables shell-escape "regardless of the presence of ... any other options". Set both.
- The cache location honours **`TECTONIC_CACHE_DIR`**. Install and prime **in the runtime stage** (no cross-stage `COPY`), and set the `ENV` **before** the prime so the path is `HOME`-independent.
- The fallback engine is **`xelatex`**, never `pdflatex` (`fontspec` cannot load under `pdflatex`). Also note that the image deliberately installs no dev tooling from `requirements.txt`, so the container lane needs pytest added explicitly and the test tree copied.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| The document being compiled → the engine process | The `.tex` body is machine-influenced content once Phase 6 renders tuned CVs; a preamble command can reach the process unless the engine is told the input is untrusted. |
| The engine argv → the shell | A command built as a string, or interpolated from document content, is a code-execution path. |
| Build host → the image | The Tectonic tarball is fetched over the network and executed; the checksum is the only integrity control. |
| The image's package cache → the runtime compile | A cache that does not survive into the runtime layer silently turns "offline" into "needs the network". |
| `artifacts_dir` → the filesystem | Artefact paths are derived, never request-supplied; a traversal here writes outside the volume. |
