<objective>
Close the golden reproduction: **the two compiled PDFs are reduced to facts and proven to carry the same organisation, title, date and bullet content** — and give the fact store a revision log, so every rendered artefact can name the revision it was built from.

Purpose: plan 04-03 proved the renderer is deterministic against a committed golden file. That is necessary and not sufficient, because a deterministic renderer can deterministically drop a bullet. CV-R2's whole risk is that `render(cv.yaml)` and the human's document diverge silently, and the only instrument that catches it is comparing the text of two compiled PDFs — the artefact a human and an ATS actually read — with an exact-membership predicate and a fact-count floor. This plan also gives `cv_versions` its first writer, so "which revision was this PDF built against" stops being unanswerable before Phase 6 starts writing artefacts.

Output: `extract_pdf_text` beside the existing page-count helper; the fact-equivalence lane with its in-test mutation control and hostile-bullet compile; and `app/db/repositories/cv_repo.py` with its revision-log tests.

**MVP framing — user story (MVP_MODE active):** **As** the job seeker whose CV is my livelihood, **I want to** see proof that the PDF the tool generates carries every fact from my real CV — and be able to say which revision of my CV it came from — **so that** I can trust a generated file enough to attach it to an application without re-reading it line by line.

**Covers:** success criterion 1's fact-equivalence half (CV-03), the end-to-end half of CV-06, and the revision-persistence half of CV-01.
</objective>

### Decisions this plan implements

- **D-68** — the golden reproduction is **two tests with two failure classes**. Plan 04-03 shipped the byte-exact renderer half in the hermetic lane; this plan ships the second half, which extracts text from the two compiled PDFs and measures the artefact a human and an ATS actually read. `render(cv.yaml)` and the human's document can never be byte-comparable — they are different templates by design — so the only meaningful comparison reduces both sides to facts.
- **D-70** — **normalise, then check membership**. Normalise first (collapse whitespace, fold ligature characters, join hyphenated line-breaks, unify dashes and quotes), then assert every organisation, title, date and each bullet's token-shingle is present on the other side. A fuzzy-ratio threshold was rejected because a high ratio over a long section can hide exactly the dropped bullet CV-R5 exists to catch. The whitespace-insensitive canonical form is applied because the extractor can drop a space entirely and would otherwise fail a **correct** document.
- **D-72** — the golden test **proves it can fail** by in-test mutation: after asserting equivalence against the correct fact store, load a deep copy, mutate one bullet's text and shift one date, render it, and assert the equivalence check now fails. A fact-count floor rides along in the same test so an empty extraction cannot pass.
- **D-77** — every accepted revision snapshots into the revision table through `app/db/repositories/cv_repo.py` (takes an `AsyncSession`, never commits — the caller owns the commit), inserting the fact payload, the schema version, a label, a source, and the current-row flag with the previous row's flag cleared.
- **D-69** — the PDF half runs as a **marked lane inside the container**: its own pytest marker (registered by plan 04-01) plus a skip-if-the-engine-is-absent guard, documented in plan 04-05's runbook. The real gate is `docker compose run --rm app pytest -m latex`.

### Resolved-at-research details this plan must not re-derive

- The extractor is **lossy in two ways**: it does not expand ligatures by default, and it drops spaces. `squash` (plan 04-03) is the answer; collapsing whitespace is not, because a space that was never emitted cannot be restored.
- The repository's ordering tie-break must be `created_at` descending **then id descending**, because two revisions written within one second share a `created_at` — the same rule the existing call-audit read uses.
- The revision table's columns are **nullable** apart from the timestamp, so the repository must supply its fields explicitly rather than relying on the schema to reject omissions.
- The schema-version column is a bounded string with no check constraint, so the vocabulary is application-level: validate the source value **before** issuing SQL and raise a clear error rather than a raw integrity error.
- **No migration is added.** Both CV tables ship in migration 0001, and the migration contract test asserts the recorded head is exactly `0003`; adding a revision would fail that test.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| The compiled PDF, read back through the extractor | The extractor is lossy and its output is untrusted-shaped text; the comparison must be exact after normalisation and must never be relaxed into a ratio |
| The fixture fact store, mutated in test | The control that proves the predicate discriminates — the same input class an attacker or a bug would produce |
| The database session to the revision table | Write ownership: the repository must never commit, or a caller's transaction is silently split |
| The schema-version value across two type systems | An integer in the document format, a bounded string in the column — a silent coercion makes a later drift check meaningless |
| The marked lane to the developer's default test run | A lane that skips silently looks green; a lane that runs by default spawns an engine that is not installed |
