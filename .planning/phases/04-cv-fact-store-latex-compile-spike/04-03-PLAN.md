### Resolved-at-research details this plan must not re-derive

- Jinja's compiler emits `str(environment.finalize(<expr>))` when `autoescape` is false, and literal template text **does not go through `finalize` at all** (verified against the installed Jinja 3.1.6, `compiler.py:1470-1472` and `:1483-1487`). That is *why* one `finalize` is a complete choke point.
- `finalize` sees the **raw** value and must tolerate non-string values (ints, `None`, lists) without raising.
- `escape_tex`'s set is the ten STACK.md Q6 characters, **ordered with the backslash first**, so an escape's own replacement text is never re-escaped.
- Unicode and ligatures are deliberately **not** escaped: `escape_tex` handles TeX-special ASCII only; non-ASCII passes through to a Unicode-enabled engine.
- `unicodedata.normalize("NFKC", ...)` expands the ligature presentation forms, so no hand-written ligature table is needed.
- `pypdf` **drops spaces**, so the shingle membership check must run on a whitespace-stripped canonical form (`squash`) or a correct document fails.
- `cv_versions.schema_version` is `String(32)` while the YAML value is the int `1` — the two must never be compared directly (this plan loads and asserts the int; plan 04-04 stores the string).

| Boundary | Description |
|----------|-------------|
| `cv.yaml` (human-authored, local) to the fact store | Semi-trusted input; a typo'd key or an omitted field, if tolerated, would become invented CV content |
| `cv.yaml` values to the rendered `.tex` | Every interpolated value crosses into a document a TeX engine will execute; this is also where Phase 6's untrusted listing text will arrive |
| `bullet.text` to the future LLM prompt (Phases 5 and 6) | Facts become prompt content; the enumerated-id design is what keeps a fact an id rather than free text |
| `.gitignore` to git | The only mechanism keeping the user's real CV out of a commit |
| Template text to the rendered document | A template author types literal LaTeX; that is a code change, not user content |

| T-04-16 | Tampering / Repudiation | an ID silently preserved across a content edit | medium | mitigate | IDs derive from immutable identity only; a text edit retires the old ID and introduces a new one, asserted by a dedicated test (the D-64 claim nothing else covers); collisions are recorded rather than hidden. |
| T-04-17 | Repudiation | a fabricated fact entering the store through a default | high | mitigate | No default-filling anywhere: every required field's absence is a load failure, asserted field by field; extras are forbidden so an unknown key fails; the importer's "unresolved is not empty" rule arrives with plan 04-05, and this plan's models are what make the two distinguishable. |

| T-04-19 | Tampering | a template silently changing the rendered bytes | medium | mitigate | The byte-exact golden file is committed, compared with a bytes read, never auto-overwritten, and accompanied by a mutation control proving the comparison can fail; `.gitattributes` pins the line endings so a platform checkout cannot change the bytes. |
| T-04-20 | Denial of Service (self-inflicted) | a fact store whose IDs are not unique, or a comparison that hides a loss | low | mitigate | ID uniqueness is asserted at load; the comparison is strict membership with a fact-count floor, so an empty extraction cannot pass, and a fuzzy ratio is explicitly rejected in the predicate's docstring and its guards. |
| T-04-SC | Tampering | package installs in this plan | low | accept | This plan installs no package. `pyyaml`, `jinja2`, `pydantic` and `markupsafe` are already installed and were gated or pre-existing; plan 04-01 owns the only install in this phase. |
