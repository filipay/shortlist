# Plan 04-01 — The two new dependencies, behind a human gate

**As a** job-seeker who runs this on my own machine, **I want to** add exactly two reviewed dependencies — one to read my `cv.yaml`, one to read the PDF the engine produces — **so that** the phase's supply-chain surface stays a pair of human-approved exact pins and nothing else.

<objective>
Install and pin `pypdf` (absent) and promote `pyyaml` from dev-only to runtime (present at `6.0.3`) — behind a blocking human checkpoint, because the package-legitimacy gate returned `SUS` for both — and widen `pyproject.toml`'s pytest configuration so the new `latex` lane can never leak into the hermetic default pass.

Purpose: `pypdf` and `pyyaml` are the only two runtime additions this phase needs, and both are load-bearing for a user-visible promise. `pyyaml` is the only way to read `cv/cv.yaml` (there is no stdlib YAML), and it is currently declared **dev-only** — so the container would build without it and the fact store would fail at import only in production. `pypdf` is how the phase measures the artefact a human and an ATS actually read, and it is **not installed at all**. The legitimacy gate flagged both `too-new` / `unknown-downloads`; the protocol is explicit that a `[SUS]` verdict is gateable only by a human and that legitimacy checkpoints are never auto-approvable in any mode.

Output: `pypdf` installed at a human-approved exact pin into the default-lane interpreter, both pins mirrored in both manifests, `pyyaml` removed from the dev group, the `latex` marker registered and excluded from `addopts`, and a guard test binding each declaration to the installed distribution.

</objective>
