<objective>
Complete the two-board slice and make the adapter port demonstrably extensible: Indeed searches land in
the same normalised shape, the Ireland country guard is pinned, and a third source can be added
without touching the pipeline — the property SRC-04 and the project's Key Decisions table both rest on.

Purpose: LinkedIn and Indeed are the two boards the phase goal names. They differ in capabilities, and
the capability system is what stops the tool from silently ignoring a filter the user believes is
applied (SRC-09). This plan is where that declared-and-warned path becomes real and where a third
adapter is proven to be a one-module change.

Output: the Indeed adapter and its regression guard, the registry-extensibility test, the capability
warning test, and the domain-purity AST test.

Recalled-prohibition ownership for this plan: the only recalled prohibition that owns an 01-04
capability is the no-credential/no-session acquisition rule — a second adapter is a second surface
where an authenticated path could reappear — and it is recorded in `must_haves.prohibitions`. The
other recalled prohibitions own other plans, not this one: PII persistence owns the ingest boundary
(01-05) and the schema (01-02), probe-volume escalation owns the operator probe (01-07), and discovery
redaction owns the opencode boundary (01-06).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| job board → transport | untrusted payload crosses into the process (second board, same contract) |
| registry → adapters | a newly registered adapter is code the pipeline will execute |
| domain → outside world | purity is the assertion that no I/O can be reached from domain logic |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-18 | Tampering | a filter silently ignored, corrupting the "why is this in my queue" story | high | mitigate | Capability compilation returns explicit warnings; `exclusive_filter_groups` is enforced; asserted by `tests/sources/test_capabilities.py` |
| T-01-19 | Spoofing | an unvetted adapter registered into the live registry | medium | mitigate | Registration is code-reviewed source; the test registers only a test-local class and the pipeline never discovers adapters dynamically from untrusted input |
| T-01-20 | Information Disclosure | a new adapter reintroducing a credential or email path | high | mitigate | The port shape forbids both; the PII mapping is shared with LinkedIn and pinned by plan 01-05's scans and plan 01-02's schema test |
| T-01-21 | Tampering | geography silently defaulting to the wrong country | high | mitigate | `country_indeed` is sourced from `settings` and pinned by a regression guard that fails on any other value |
| T-01-22 | Tampering | architecture decay — I/O leaking into the pure domain | medium | mitigate | The AST import-discipline test fails on any forbidden import under `app/domain/` |
| T-01-SC | Tampering | package installs | low | accept | No new dependency; consumes the plan 01-01 lock |
</threat_model>
