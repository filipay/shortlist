<objective>
Bring up the **walking skeleton**: a bootable FastAPI app, the one-way migration 0001, a real DB
read **and** a real DB write through the two-key Tier-1 upsert, a browsable queue page, and a
`docker compose up` deployment path that serves everything locally.

**User story (derived from the ROADMAP Phase 1 goal — not invented scope):**
**As a** job-seeker running this tool locally, **I want to** start the whole stack with one command
and open a queue page that shows real, persistent listings plus a per-source health view, **so that**
the search→judge loop costs minutes instead of hours and I can trust the foundation it is built on.

Purpose: this plan carries the phase's one-way door. `migration 0001` describes the past
(`first_seen_at`, `listing_events`, `factor_scores_json`, `applications.cv_artifact_id`, …) and cannot
be backfilled (D-20 / PITFALLS P8). It also establishes the cross-cutting seams every later phase
inherits: the settings surface (PLAT-04), the auth seam (PLAT-03), the vendored asset pipeline
(UI-07), and the Alembic-in-the-entrypoint deployment shape (PLAT-01).
Output: a runnable skeleton (`alembic upgrade head` → `uvicorn app.main:app --workers 1`) whose `/`
page renders from the database, plus the deployment manifest and the DB guarantee tests.
</objective>
