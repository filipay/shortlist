<objective>
Make per-source health observable and wire the external opencode boundary safely: a cached liveness
probe per board, a boot-tolerant `/health` that reports database, opencode and every source, a visible
health strip, and a discovery client whose redaction boundary is proven by test.

Purpose: SRC-07 says the user *can see* per-source health and a probe that detects silent breakage —
a JSON-only surface would half-satisfy it, so the strip is a real UI deliverable. The discovery client
is the phase's most concrete security hazard: the response contains a plaintext provider key (D-11),
and one stray log statement puts a live credential on disk.

Output: the probe orchestration, the opencode health/discovery client, `/health`, the source health
read model, and the health strip.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → opencode server | privileged external service; its discovery response carries a live credential |
| browser → /health | health data is not secret but must not carry a raw upstream payload |
| app → job boards | the probe is outbound and must stay cached and cheap |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-29 | Information Disclosure | the plaintext provider key in `GET /config/providers` reaching a log or the DB | high | mitigate | Parse into a model with only provider/model ids; never bind the raw body; `tests/test_discovery_redaction.py` scans `caplog` and every table for a sentinel value |
| T-01-30 | Information Disclosure | `/health` echoing a raw upstream payload | medium | mitigate | The response is built from typed fields only; the test asserts no raw-payload field exists |
| T-01-31 | Denial of Service | `/health` hammering a job board on every page load | high | mitigate | TTL cache in `probe_all()`; asserted by the invocation counter in `tests/probe/test_probe.py` |
| T-01-32 | Denial of Service | a hung outbound call blocking the single worker | medium | mitigate | The client uses a bounded timeout and never raises; the probe never escalates or retries hard (P2) |
| T-01-33 | Spoofing | a block page returning 200 and being read as healthy | high | mitigate | `probe()` asserts a structural marker and the absence of stop signals, not merely a 200 |
| T-01-34 | Repudiation | a degraded source presented as healthy | medium | mitigate | `degraded` is a distinct state rendered in the strip; the contradiction between `ok` and no new listings is plan 01-07's signal S4 |
| T-01-SC | Tampering | package installs | low | accept | `httpx` and `tenacity` are already pinned in plan 01-01; this plan adds no dependency |
</threat_model>
