<objective>
Make the new ceilings real configuration rather than aspirational knobs: **the config guard asserts
them, the container forwards them, and the operator can find them.**

Purpose: PLAT-04 is a Phase-1 requirement that keeps constraining new work — "every limit, threshold,
country and budget is configuration". A `Settings` field nobody forwards to the container is a knob
that silently does nothing, which is the exact failure `compose.yml:21-25` already documents for the
Phase-2 settings.

Output: the config-guard extension, an env-tunability behaviour test, the compose passthrough entries,
and the `.env.example` documentation.

**MVP framing — user story (MVP_MODE active):** **As** the local operator, **I want** to raise the
completion timeout or lower the retry count from my `.env` without editing code, **so that** a slow
model or an expensive retry policy is a configuration change.

**Covers:** PLAT-04's constraint on PLAT-02's new ceilings.
</objective>
