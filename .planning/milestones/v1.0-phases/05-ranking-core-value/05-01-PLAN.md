## Reversibility

Backing this change out is a two-step, additive-only operation. The migration is purely additive (one new table, no column dropped, renamed or made NOT NULL, no existing row rewritten), so `alembic downgrade 0003` drops exactly `ranking_config` and leaves every other table intact. The ranking stage is disabled by removing the single `start_ranking_task(...)` call site in `run_pipeline`; `run_pipeline` then behaves exactly as it does today, writes zero `llm_calls` and zero `scores` rows, and the queue renders unranked because `_enrich` degrades a missing score to `total_score = None`. `app/domain/rubric.py`, `app/domain/schemas/ranking.py`, `app/db/repositories/score_repo.py`, `app/db/repositories/ranking_config_repo.py` and `app/pipeline/rank.py` are deletable modules with no other importer once that call site is removed. This is the natural gate D-94 requires: ranking is optional, and disabling it leaves the application exactly as it is today.
