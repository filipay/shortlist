<objective>
Close the PARTIAL must-have truth (#14) on the D-94 optional-ranking posture: an unreadable CV fact store (a non-UTF-8 `cv.yaml`) currently raises `UnicodeDecodeError` straight past the ranking stage's `(CvFactStoreError, OSError)` guard, so the detached task dies silently instead of taking the documented skip path.

Purpose: the module docstring and D-94 promise that an absent **or unreadable** fact store leaves ingest untouched, with zero LLM calls and a legible log. Today that promise holds for invalid YAML and missing files but not for undecodable bytes, which is the same operator-visible situation with a different exception class. Fixing it at the fact-store boundary means every caller — ranking now, tailoring later — sees one typed failure.

Output: `load_facts` re-raises the read failure as one path-qualified `CvFactStoreError`; a unit test pins that contract; an end-to-end test pins the detached task's clean skip and its `fact_store_absent` log; the obsolete strict-xfail sentinel is retired.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator filesystem → `load_facts` | A `cv.yaml` outside the repo is parsed; its bytes, encoding and readability are not under the application's control |
| `load_facts` failure → detached ranking task | A load failure crosses into the fire-and-forget task, where an unhandled exception is never retrieved |
| parsed CV document → ranking prompt | The document's content travels to the model as user content only (unchanged by this plan) |
