## Fix route and tradeoff

**Chosen: route (a)** — exclude a non-positive candidate count at the run read boundary (`run_repo._optional_int`), with the template ratio gate tightened to a truthiness check at the render site.

**Why (a) over (b):** route (b) (omit `survivors` from `_assemble_run_reason`'s payload on the bookkeeping-failure path) fixes the one pipeline producer. The verifier's gap names two further reachable states that bypass that producer entirely — "a hand-edited or older-build row reaches it too" — and the demanded regression test seeds the persisted `0` directly rather than driving the pipeline, so (b) alone would leave both the hand-edited row and the required test failing. Route (a) is the smaller, more localised change and makes the invariant hold for every producer at the single read boundary `RunSummary.candidate_count` where the strip's consumers all route through.

**Honesty check — is a genuine zero-coverage run misrepresented?** No. A run that scored zero survivors never starts the ranking pass (`app/pipeline/run.py:904` starts it only when at least one non-excluded candidate exists), so `runs.ranked_count` stays NULL and the strip's outer `ranked is not none` guard renders nothing at all. The only rows that reach the ratio have `ranked_count` set, i.e. ranking actually ran, i.e. an honest run had at least one candidate. The `survivors == 0` with `ranked_count > 0` state is therefore internally inconsistent and only reachable via the fabricated path or an edited/older row — exactly the state that must not print a ratio. A run where ranking ran but every call failed honestly renders `Ranked 0 of 30` and is untouched by this change.

**WR-06:** yes, this closes it. `05-REVIEW.md` WR-06 is "`run.py:509-538` + `queue.html:140` — swallowed bookkeeping can still print `Ranked N of 0`". The defect is the printed claim, and route (a) makes that claim impossible regardless of how the zero was persisted — the strip's user-visible failure mode is gone, and the `queue.html:140` line the verifier flagged is itself hardened. The latent fabricated `survivors: 0` in `run.py`'s payload is left in place deliberately: it is invisible to this surface after the fix, and changing it would be route (b) plus a wider blast radius on `_assemble_run_reason`'s other consumers for no additional user-visible gain.

## Reversibility

Reversible. The production change is one comparison inside a private read-model helper plus a one-token template conditional; restoring `_optional_int`'s raw `return int(value)` and the `is not none` gate restores the previous behaviour exactly, and the two new tests are the only artefacts that would go with it. No migration, no persisted shape change, no data rewrite — `runs.reason_counts_json['survivors']` and `runs.ranked_count` are read as they already are.
