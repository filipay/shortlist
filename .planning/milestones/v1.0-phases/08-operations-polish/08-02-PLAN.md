# Plan 08-02 — The phone is a first-class journey target

**As a** job-seeker who checks the queue on my phone before I get to a laptop, **I want to** read every journey page comfortably at phone width with nothing hidden behind a horizontal scroll, **so that** the morning loop costs minutes wherever I am rather than being a desktop-only tool.

> **MVP framing note.** The ROADMAP `**Goal:**` line for Phase 8 is an outcome, not a user-story sentence; the story above is derived from it plus PROJECT.md's Core Value and recorded rather than invented, matching the Phase 4 precedent.

<objective>

### Decisions this plan implements

- **D-159** — the primary journey must be genuinely comfortable on a phone: queue, listing detail, the health page, the run control, and the applications tracker. Admin surfaces must not break but stay desktop-first.
- **D-160** — responsive rules are authored in `assets/tailwind/input.css` and rebuilt with the pinned CLI into `static/vendor/app.css`; card-reflow is used **only** for the journey tables; every other table keeps its markup wrapped in an accessible scroll region; **no JavaScript**.
- **D-161** — verification is a `/gsd-ui-review` 6-pillar audit over the responsive surfaces plus a documented operator-run checklist naming viewport widths 320/375/768 crossed with the journey pages.
- **D-162** — on a phone a queue row restacks **all** the data the desktop row shows, as label:value lines, with nothing hidden.
- **08-UI-SPEC §A / §Component Inventory** — the exact three new class tokens and the breakpoint decision.

### Breakpoint decision (recorded, not left implicit)

Card-reflow applies **below the `md` breakpoint** (Tailwind's `md` is 768px, i.e. 48rem, expressed as a `min-width` query). Author the reflow block as a `@variant max-md { … }` at-rule inside `@layer components`: the pinned CLI compiles that to the exact complement of `md`, so the two regimes tile the width axis with no gap and no hard-coded boundary in our source. Do **not** write a `max-width: 767px` media query — it and Tailwind's `md` leave 767.01–767.99px in *neither* regime, which is exactly the operator-checklist width the audit would then disagree with itself about (RESEARCH Pitfall 8). The pinned CLI was verified to compile `@variant md` and `@variant max-md` to the exact `min-width` / `max-width` complements at 48rem.

### Verified environment fact (do not re-derive)

The pinned CLI is present and reports `v4.3.3`: `./node_modules/.bin/tailwindcss`. The build command the Dockerfile uses, and therefore the one this plan uses, is:

`./node_modules/.bin/tailwindcss -i ./assets/tailwind/input.css -o ./static/vendor/app.css --minify`

`tests/test_stylesheet_coverage.py` **skips visibly with a named arming command** (never silently passes) when the CLI is absent — that precedent is what every command in this plan relies on.

### Historical warning (from plan 07-13)

`static/vendor/app.css` had been hand-appended out of sync with its source, and a rebuild-before-backfill deleted 30 template rules. The source is in sync now: **author the CSS edit first, then rebuild.** Never edit the built artefact by hand.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTML template → CSS rule set | A class used in a template but absent from the source stylesheet is an unstyled control; the coverage guard fails closed on it |
| source stylesheet → committed build artefact | `static/vendor/app.css` is committed and served; hand-editing it makes the byte-identity guard fail and a later rebuild silently deletes the hand-written rules |
| rendered label text → screen reader | `content: attr(data-label)` renders the label visually; a mismatch with the `<th>` text presents two names for one field |
| the app → third-party asset hosts | UI-07 requires every asset vendored; any new external reference is a privacy and availability regression |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-05 | Tampering | `static/vendor/app.css` hand-edited out of sync with its source | high | mitigate | The rebuild is part of the task and `tests/test_stylesheet_coverage.py` asserts byte-identity of the committed artefact against a fresh pinned-CLI build; the runbook and the plan both state that the only writer is the build. This is the 07-13 failure mode, deliberately re-guarded. |
| T-08-06 | Information Disclosure | a new external asset reference on a journey page | medium | mitigate | No asset reference is added; `tests/test_no_cdn.py` guards UI-07 and is run in each affected task. |
| T-08-07 | Spoofing (accessibility) | a `data-label` that disagrees with its column header | low | mitigate | The action requires the label to equal the `<th>` text verbatim, and the acceptance criteria assert every cell carries one; the operator checklist's 320/375 cells read the labels against the header words. |
