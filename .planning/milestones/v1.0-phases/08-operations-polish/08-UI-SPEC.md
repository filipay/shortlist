## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — no shadcn, no `components.json`. This is not a React/Next/Vite stack, so the shadcn init gate does not apply and no registry is initialized. The design system is a **bespoke Tailwind CSS 4.3.3 build**; its source of truth is `assets/tailwind/input.css`, rebuilt with the pinned CLI (`Dockerfile:14-19`, `tailwindcss@4.3.3` + `@tailwindcss/cli@4.3.3`) into the committed `static/vendor/app.css` (served at `/static`, linked in `base.html:8`). |
| Preset | not applicable |
| Component library | none — server-rendered Jinja2 partials + HTMX 2 + Alpine 3. Reusable "components" are **CSS class tokens + HTML partials**, enumerated below. |
| Icon library | none — Unicode glyphs only (existing precedent: `&#9733;` saved, `⚠` warning, `—`/`→` in `app/web/filters.py`). Do not add an icon font or SVG sprite. |
| Font | `--font-sans` (system UI) body; `--font-display` (ui-serif/Georgia) headings; `--font-mono` for ids, paths, counts and machine tokens. Declared in the `@theme` block. |

**Rule for this phase:** author responsive CSS **only** in `assets/tailwind/input.css`, then rebuild
`static/vendor/app.css` with the pinned CLI (D-160 — never hand-edit the built artefact; the
`tests/test_stylesheet_coverage.py` byte-identity guard enforces this, plan 07-13). **Do not
introduce a second system.** New CSS is limited to the `@media` reflow block and the **New tokens
this phase may add** list in §Component Inventory — each copies an existing rule's declaration block,
and is called out there with the existing rule it mirrors.

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Existing anchor values (reuse, do not rewrite): `#content` padding `1.5rem 1rem 3rem` (24/16/48); `section` margin-bottom `2.5rem` (40); `.queue-table` / `.health-table` cell padding `.875rem 1rem` (14/16); `.settings-card` / `.danger-card` padding `1.25rem` (20).

**Exceptions:** the shipped sheet uses Tailwind's default micro-steps *between* the 8-point values — 6px (`.375rem`), 10px (`.625rem`), 12px (`.75rem`), 20px (`1.25rem`) — throughout. Phase 8 reuses those shipped rules unchanged; reflowing them would reflow every existing surface.

**Touch targets (hard requirement this phase):** D-159 makes the phone a first-class journey target and the 06→07 UI review recorded the 44×44px minimum as *declared but unimplemented*. **Every compact or icon-like control in the journey must clear 44×44px** via `.touch-target` (`min-height:2.75rem; min-width:2.75rem`): the `Copy answer` button, the `History (n)` `<summary>`, the queue/tracker filter labels (`.queue-toggle`), `.nav-link`, the pager buttons, the health page's compact links, and the prune controls. `Run search now` (`#run-search-now`, padding `.625rem 1.25rem`, font-size `1rem`) already exceeds it and is left unchanged.

## Phase 8 Surface Contracts

No new JavaScript (D-160). Every surface is **server-rendered and fully usable with JS off**: HTMX
enhances nothing that this phase adds (the prune preview is a plain form POST, not an HTMX swap), and
Alpine is not used for any new state. All CSS is authored in `assets/tailwind/input.css` and rebuilt
into `static/vendor/app.css` with the pinned CLI.

### A. Responsive contract (D-159 / D-160 / D-162)

**Breakpoint (discretion, D-160 — stated decision):** card-reflow applies **below 768px**
(`@media (max-width: 767px)`); at ≥768px the desktop table is used. Rationale: this makes each of the
operator-checklist widths (D-161) verify a distinct regime — **320px and 375px** exercise the reflow
layout; **768px** exercises the desktop table inside its accessible scroll region.

**Card-reflow — journey tables only.** `.queue-table` (queue, applications) and `.health-table`
(health strip, `/health`) get the phone treatment. It is implemented with a **`data-label` attribute
on every `<td>`** plus CSS only (the standard no-JS responsive-table pattern):

- Each journey-table `<td>` gains `data-label="<the desktop column header text>"` (e.g.
  `data-label="Posted"`, `data-label="Excluded by"`). Labels must equal the `<th>` text verbatim so
  the phone line reads the same word as the desktop header.
- `@media (max-width: 767px)` sets the table, `thead`, `tbody`, `tr`, `td` to `display:block`;
  visually hides `thead` (clip, not `display:none`, so header semantics survive best-effort); gives
  each `<tr>` a bottom border and padding as a card; and renders each cell as a label:value line via
  `td[data-label]::before { content: attr(data-label); font-weight:600; color:var(--color-muted); }`
  on its own line above the value.
- `td:not([data-label])::before` renders nothing, so a cell with no label degrades cleanly.

**D-162 — the queue row restacks ALL the data the desktop row shows**, as label:value lines, with
nothing hidden and nothing requiring a second tap. The full set (from `_listing_row.html`): title
(with its `Details` link), signals/badges, company, location, source (and the `Apply` chip), posted
date, **`Excluded by`** (when the column is present), and **actions** (the Save/Hide controls). The
tracker row restacks: listing/company, `Stage`, `Applied`, `Next action`, `Latest note`, and
`Actions` (the two forms plus the `History (n)` toggle). The health row restacks: `Source`, `Health`,
`Last success`, `Returned`, `Field fill-rate`.

**Every other table keeps its current markup, wrapped in an accessible scroll region.** Wrap the
existing `<table>` in `<div class="table-scroll" role="region" tabindex="0" aria-label="<name>">`:
the criteria rule list needs none, but the merges table (`Merges`), the runs table (`Run history`),
and the detail page's factor table (`Fit breakdown`) do. `tabindex="0"` makes the region reachable by
keyboard (so it can be scrolled without a pointer); the `::focus-visible` ring is already global.
**Wrap the table, never put `role="region"` on the `<table>`** — that would override its table role.

**Phone controls.** Below 768px the journey's stacked controls go full-width inside the reflow:
`#queue-filters` children (`.queue-toggle`, `.queue-sort`, `.queue-threshold`), `#run-search-now`,
and the pager buttons each take `width:100%` (or `flex:1 1 auto`) so nothing needs a pinch-zoom.
`#queue-pager` stays `display:flex` and may wrap. Admin surfaces (criteria editor, merges audit, runs
history, settings) stay desktop-first and are **not** reflowed (D-159).

**Acceptance (D-161).** Verification is the project's existing `/gsd-ui-review` 6-pillar audit over
the responsive surfaces, plus an operator-run checklist in a runbook naming the viewport widths
**320 / 375 / 768** crossed with the journey pages (queue, listing detail, `/health`, run control,
applications tracker) — the `docs/runbook-compose-smoke.md` precedent, since Docker and a browser are
absent from the agent sandbox.

### B. `/health` page — `GET /health` (a new HTML route)

> **Name collision to resolve at plan time:** `GET /health` currently serves the **JSON** endpoint
> (`app/api/health.py`). D-155 calls for a human page at `/health`. The page route and the JSON
> endpoint must not both claim `/health`; the page takes the human path (e.g. `/health` served as
> HTML, with the JSON moved to `/health.json`) unless the plan chooses otherwise. The contract below
> is about the **page**; it must agree with the JSON on opencode reachability and `auth_configured`
> (D-138, already enforced once — both read `app.llm.auth_configured`).
>
> **RESOLVED (decision, 2026-10-14):** the JSON endpoint **keeps `/health`** (zero churn — 25
> `.json()` assertions, the `test_auth_seam.py` route inventory, and `scripts/compose-smoke.sh` all
> pin it); the page gets its own path **`/status`**. FastAPI is first-match-wins, so the page route
> must not also declare `/health`. §E's nav href follows this.

The page **reads the DB only** and puts **no request on a job board** (D-156): source status is
computed from recorded run outcomes and recorded stop signals, never a live probe on page view. Like
`_health_strip`, it is a **decorative read that never raises** — every failure degrades to data.

Layout, top to bottom, H2 `Health`:

1. **System section** — `<section id="health-system">`, H3 `System`, then the intro line, then a
   `<dl class="health-system">` with the four dependency rows (Database, LLM backend, LaTeX engine,
   CV fact store). Each row: a `<dt>` label and a `<dd>` containing a `.health-badge` plus the detail
   text. Assembled from data that already exists (D-157) — `app/api/health.py`'s `_opencode_report` /
   `_tectonic_report` / `_cv_report` are the same computations, exposed without raising.
2. **Schedule line** — a `.ranking-strip`: `Next run in 3h 12m` with the countdown in a
   `.reason-value` chip; `Scheduling off` when the schedule is disabled; the D-154 missed-run notice
   when the last scheduled run was skipped.
3. **Last-run line** — a `.ranking-strip`: the last run's status and its one-line reason
   (`reason_sentence`), linking to `/runs`.
4. **Adzuna verdict line** (D-158) — read-only evidence with the number in it, plus the probe-document
   link. No control.
5. **Per-source table** — the **existing `_health_strip.html` partial included verbatim**, so the page
   and the queue strip cannot disagree (D-138). It renders the LLM line, the CV line and the
   `.health-table`.

## Assumptions (resolved here, not re-asked)

CONTEXT.md deliberately leaves these to this document's discretion; each is decided in the option most consistent with the shipped design system (D-160) and recorded rather than blocking:

1. **Breakpoint** — card-reflow below **768px** (`@media (max-width: 767px)`); desktop table at ≥768px. Chosen so 320/375 and 768 each verify a distinct regime (§A).
2. **Reuse, not new components** — the `/health` page includes the existing `_health_strip.html` partial; the system section reuses `.health-badge`, the status lines reuse `.ranking-strip`, the prune preview reuses `.capability-warnings` + `.settings-counts`, and every form reuses `.field` / `.form-actions` / `.settings-banner`. Only three class tokens are added (§Component Inventory), each copying an existing rule.
3. **Route shape** — the `/health` page takes the human path and the JSON endpoint moves to `/health.json` (or equivalent), so the two do not both claim `/health`; the plan may resolve the exact paths, but the page-vs-JSON agreement on `auth_configured` (D-138) is mandatory.
4. **Schedule off switch** — an `Run once a day` checkbox (D-152 names no off switch); off is the `Scheduling off` state.
5. **No JS** — the prune preview/confirm are plain full-page POSTs, not HTMX swaps (D-160); Alpine is untouched.
6. **Touch targets** — `.touch-target` (44×44px) is applied to the compact controls the 07 audit found sub-minimum, closing that review's Top Fix 1 within this phase's responsive scope.
