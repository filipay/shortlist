<objective>
Make the app's LLM backend speak the opencode V2 HTTP API end to end, while the retained V1
path keeps working (D-147/D-148). This plan is the **tracer**: it proves on the thinnest
possible slice that a schema-constrained completion still works — detected surface, session
create, `generate`, text extraction, salvage, typed result — with a real runnable check in the
default lane (no socket).

Purpose: the pinned V1 contract is dead on opencode 2.0.26 (legacy root routes return SPA HTML,
`POST /session` is a hard 405), so every ranking / tailoring / drafting / extraction call fails
with `JSONDecodeError`. Nothing downstream of the LLM port works until this slice is proven.
Output: the V2 wire constants and request builders, a detection module, a V2 completion arm in
`OpenCodeServerBackend`, and the Wave-0 test scaffolds the rest of the phase builds on.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → opencode server | The app sends a single prompt assembled from frozen instructions plus untrusted listing/CV text and consumes the model's free text. |
| opencode response → app memory | The `generate` body is model prose derived from untrusted text; only extracted identifiers may leave the call. |
| operator → app config | `OPENCODE_SERVER_PASSWORD` crosses from the operator's environment into every outbound request. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
