## Decisions Made
- **Committed-subset diff (not strict equality).** The committed fixture is a hand-written *projection* (D-149) whose own note states "unrelated OpenAPI churn cannot fail the contract test". Since the slice omits two members the live 2.0.26 spec carries (`id` in the session request properties, the optional `variant` in `Model.Ref.properties`), strict equality would make the lane fail on its first run for non-drift reasons. The diff therefore honours a fact when every committed member is present in the live spec — a rename or removal still fires, which is the drift D-150 exists to catch. This mirrors the "validate against the real spec, 0 diffs" discipline the V1 lane recorded.
- **Contract-agnostic selftest signal.** `bool(result.ok and result.data is not None)` is true for a successful V1 call and a successful V2 call (both set a validated `.data`), so the V2 success path stops reading "absent".
- **PROVISIONAL negative assertion.** Per 07.1-RESEARCH OQ2/P9 the exact rejection shape is unobserved, so the assertion prints the observed `status`/`error` in its message for reconciliation on the first operator run.

**1. [Rule 1 - Bug] The committed slice is a lossy projection; the diff is committed-subset, not strict equality**
- **Found during:** Task 1 (operator contract lane retarget)
- **Issue:** The plan's fact list (session request properties, `Model.Ref` properties) does not match the committed slice's members under a strict-equality diff: the live 2.0.26 `/openapi.json` carries `id` in the session POST properties and `variant` in `Model.Ref.properties`, neither of which the hand-written slice records.
