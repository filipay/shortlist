## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| App → opencode HTTP API | The app speaks V1 or V2 depending on the detected surface, over HTTP basic auth (`opencode` / `OPENCODE_SERVER_PASSWORD`) | Untrusted listing/CV text out; model prose back |
| `discover_models` → `/api/model` + `/api/provider` | Discovery response carries a plaintext provider credential | Provider/widget credential (sensitive) |
| `_auth()` → `httpx.BasicAuth` | The only place the server password is consumed | `OPENCODE_SERVER_PASSWORD` (local secret) |
| `/health` → UI | Backend reachability report surfaced to the browser | Boolean `auth_configured` only (never the secret) |
| Prompt assembly (`to_generate_prompt`) | V2 has **no `system` field**; frozen instructions and untrusted text share one prompt | Untrusted listing text adjacent to frozen instructions |
| Operator live lane → running server | Operator-run contract/live tests fetch `/openapi.json` + `/api/info` | Spec document (public) + auth token (local secret) |

## Residual / Non-Blocking Observations

These are **not** open threats and do **not** count toward `threats_open`; they are recorded so the claims above are not read as broader than the code delivers (#2119 / CONVENTIONS rule 6).

1. **Latent `repr()` exposure of the password (hardening, not a live leak).**
   `Settings.opencode_server_password` is a plain `str` field (`app/config.py:60`), so
   `repr(settings)` includes the plaintext value (verified:
   `'…' in repr(settings) → True`). No application code path logs, echoes or returns
   `settings` today, so the declared T-07.1-01 mitigation ("never logged, never echoed
   in an error, never placed on a result") holds. If `Settings` is ever logged or
   dumped wholesale, the secret would surface; the cheap hardening is
   `Field(repr=False)` or `SecretStr`. Not blocking.
2. **The operator live lanes were not executed in this audit.** T-07.1-13/T-07.1-14/
   T-07.1-15 mitigations live in `tests/llm/test_contract_live.py` and
   `tests/llm/test_live_structured_call.py`, which are deselected in the default lane
   (`-m live`) and require a running, authenticated opencode 2.0.26 server. Their
   mitigations were verified by reading the test code, not by running it. The phase's
   own `07.1-VERIFICATION.md` lists these as human/operator-run items.
3. **Stale prose in `07.1-VERIFICATION.md`.** The verification report's rows 3 and
   D-136 record the superseded "empty password fails fast, issues no request" wording.
   D-136 was amended (app attempts the call; a `401` is `unauthenticated`) and the code
   reflects the amendment; the verification doc predates the amendment commits. This is
   documentation drift, not a mitigation gap.
