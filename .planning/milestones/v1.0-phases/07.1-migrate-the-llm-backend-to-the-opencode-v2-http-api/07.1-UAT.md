## Gaps

gap_id: G-07.1-1
truth: "Clicking 'Draft answers' returns usable drafted answers the user can review and copy."
status: resolved
resolved_by: af17f8e
resolved_at: 2026-10-14
reason: "User reported: 'The drafting call did not return a usable response. Your existing drafts were kept.'"
severity: major
test: 3
root_cause: >
  `DRAFT_SYSTEM_PROMPT` asked for a top-level JSON ARRAY, but `_extract_json`
  (`app/llm/opencode_server.py:1189-1216`) can only ever return the first `{...}` object,
  so an array reply yielded one answer object and `_salvage(ScreeningDraftResponse, ...)`
  rejected it (`extra="forbid"`, required `answers: list[...]`) -> status=invalid ->
  drafting_failed. V1's server-side `format` coercion hid the contradiction; V2 removed it.
artifacts: [af17f8e, 65c80a6]
missing: []

gap_id: G-07.1-2
truth: "Clicking 'Tailor CV' on a listing returns a usable, reviewable patch."
status: resolved
resolved_by: 3b74bff
resolved_at: 2026-10-14
reason: "User reported: 'The tailoring call did not return a usable patch. Try again.'"
severity: major
test: 3
root_cause: >
  The model returned a structurally-valid but semantically-invalid patch: two operations
  naming the same `bullet_id`. The rule existed only in `_validate_patch`, which runs AFTER
  `complete_structured`, so the V2 client-side schema-retry loop never saw it and the first
  bad reply failed the request one-shot. Fixed in `3b74bff` by (1) stating the
  at-most-one-operation-per-target rule in `TAILOR_SYSTEM_PROMPT` and (2) mirroring it in a
  `TailoringPatch` `model_validator`, so a duplicate-target reply becomes a `ValidationError`
  the existing loop feeds back and retries (D-140). A second, distinct cause the operator hit
  was a stale `OPENCODE_SERVER_PASSWORD` after a server restart (2.0.26 prints a new password
  each start), which failed before any model call.
artifacts: [65c80a6, 9777a83, 3a4a804, 3b74bff]
missing: []
