# Phase 07.1 Plan 02: Auth-state surfacing on `/health` and the queue strip Summary

**The operator can now see *why* the LLM backend is failing — `auth_configured` is reported on `/health` and the queue strip renders an `llm-backend-auth-missing` hint, both read from one `app.llm.auth_configured()` helper, without ever leaking the password.**

## Accomplishments

- Added `app.llm.auth_configured()` — the single definition of "is opencode auth configured" (`bool(settings.opencode_server_password)`), exported in `__all__`. `/health` and the queue strip both import it, so the report and the strip cannot disagree (D-138).
- `/health`'s `_opencode_report` now returns `{reachable, version, error, auth_configured}`. The key is inert — it never gates or changes `status` (D-08) — and carries only the boolean, never the password.
- `_health_strip` gains a fifth tuple element carrying `auth_configured()`; the queue route passes it as `opencode_auth_configured`, read from the same helper.
- `_health_strip.html` prepends `id="llm-backend-auth-missing"` in the unreachable branch when no password is configured, pointing at `docs/runbook-opencode-contract.md`. An auth-configured-but-unreachable backend keeps the existing generic text.
- Tests pin the boolean in both lanes (default `False`, patched password `True`), assert the password value never appears in the `/health` JSON, and assert the strip hint appears without a password and disappears once one is set.

## Decisions Made

- **One helper, two consumers (D-138).** `auth_configured()` is the single home of the derived boolean; neither `health.py` nor `routes.py` recomputes `bool(settings...)`.
- **Inert report field (D-08).** The boolean is added to the report dict only; `status` is unchanged.
- **Reused `llm-unreachable` class for the new line.** A brand-new CSS class would have demanded a rule in `assets/tailwind/input.css` (outside this plan's `files_modified`); the existing class keeps `tests/test_stylesheet_coverage.py` green.
