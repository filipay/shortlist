<objective>
Close the phase's fourth success criterion: a CV that fails verification is blocked — it cannot be downloaded or attached — and the verified one is previewable and downloadable.

Purpose: "repair pressure is fabrication pressure" is only true if the blocked artifact is genuinely unreachable. The repository's `ok`-only selection is the single access control, with route-level refusal as the second layer, so a blocked row cannot be served even by artifact id. And the blocking must be explainable: the user sees which checks failed, so a block reads as a reviewable outcome rather than a dead end.
</objective>
