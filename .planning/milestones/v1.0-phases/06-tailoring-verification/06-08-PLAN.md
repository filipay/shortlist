<objective>
Close GAP A (CR-01, BLOCKER) and GAP B (CR-02, major): make Layer-2 check 4 (`metric_containment`) stop hard-failing ordinary, correct CV content — by grounding an entry's location digit cores in its own region and by anchoring each region on its own entry header line — so a valid tailored CV whose entry carries a digit-bearing location, or whose bullet names a later employer, verifies and is previewable and downloadable again.

Purpose: `metric_containment` is the check the roadmap names for success criterion 3. Today it false-fails two ordinary CV shapes, both with no UI recovery (D-118's only recovery is a fresh tailor, which re-runs the same predicate): (1) `_allowed_for_entry` (app/verify/numbers.py:143) enumerates dates/org/title/bullets but not `entry.location`, while cv.tex.jinja:59-60 renders `entry.location` into that same region — so any digit in the location ("Dublin 2", an Eircode, "Remote (GMT+1)") is a surplus candidate and check 4 HARD FAILS; (2) `_entry_lines` (app/verify/numbers.py:120) starts a region at any line merely CONTAINING `squash(entry.org)`, so a bullet that mentions a later employer mis-locates the later region and pulls the earlier entry's bullet digits in, e.g. regions `[(exp/acme-2018, []), (exp/acme-2019, [5])]` -> `fail [exp/acme-2019:5]`. Both live in `app/verify/numbers.py`, so they are fixed together in one plan (the file-overlap rule), with the single VERIFIER_VERSION bump that covers both.

Output: a `_allowed_for_entry` that grounds `entry.location`, an `_entry_lines` that anchors on the entry header line (org AND title) while preserving the last-region-runs-to-end-of-text behaviour, a bumped `VERIFIER_VERSION`, the committed `digit_location_extract.txt` fixture and its `with_digit_location` builder, and the regression tests that pin both fixes plus the untouched novel-metric negative control.
</objective>
